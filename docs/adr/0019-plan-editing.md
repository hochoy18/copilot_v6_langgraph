# ADR-0019: Plan 编辑能力 — 可改参数,不可增删节点

## 状态
已接受

## 背景
HITL 阶段,Plan 预览展示给业务人员确认。完全锁定(只 approve/reject)体验差,业务人员常需要微调;完全开放(可增删节点)又会破坏 Planner 的语义完整性,且后端需要支持任意图编辑与重验证,MVP 阶段过重。

## 决策
Plan 编辑能力限定为"可改参数,不可增删节点":

1. **可改** — 每个节点的参数值、参数备注(给 LLM 看的语义)。例:Planner 生成了"按 ID 查订单",业务人员可以改 ID 值或备注。
2. **不可改** — 节点的增删、节点之间的依赖关系。这些改动需要重新走 Planner,业务人员需"驳回 + 重新描述"。
3. **驳回** — 整 Plan 取消,业务人员需重新发起用户轮次。
4. **编辑后的 Plan** — 直接进入执行阶段,不需要二次 HITL(参数级别的修改信任业务人员的判断)。

## 后果
- UX 友好,业务人员可以微调"差不多对"的 Plan。
- 节点级 DAG 结构由 Planner 掌控,完整性有保障。
- 后端需要支持 Plan diff + 应用 + 校验;LangGraph 不原生支持,需要薄薄的 Plan 应用层。
- 编辑后的 Plan 仍要进审计日志,含"修改前 → 修改后"diff。
