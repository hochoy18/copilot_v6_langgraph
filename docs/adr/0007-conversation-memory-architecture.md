# ADR-0007: 多轮会话的记忆架构

## 状态
已接受

## 背景
会话支持多轮后,每轮 Planner 拿到的上下文决定了 Plan 质量。两种极端都不行:

1. **只取近期** — "上周那个项目"这类跨多轮的引用会失效。
2. **全量原文** — 上下文无限膨胀,LLM 成本失控且信号被淹没。

## 决策
每轮 Planner 的上下文由两部分组成:

1. **记忆窗口(直接进 prompt)** — 最近 K 轮(原文、Tool 调用结果、Plan 快照)。K 是可配置参数,默认 K=5。直接喂给 LLM,信号无损。
2. **长期记忆(语义召回)** — Milvus 中存储的历史 Plan 摘要、Tool 调用摘要,每轮根据当前 User Turn 走向量召回,取 Top-N(N 默认 3)注入 Planner 上下文。召回用于"上周那个项目""上次那个客户"这类远距离引用。

记忆窗口与长期记忆在 Prompt 中用清晰的标题区分(原文 / 召回),Planner 据此分辨"当前会话上下文"与"历史参考"。

## 后果
- Milvus 写入发生在 Plan 完成 / Tool 调用完成两个时点;查询发生在每轮 Planner 调用前。
- K 与 Top-N 都做成可配置参数,但 MVP 默认值在 SPEC 中固化。
- 长期记忆的摘要策略(LLM 生成 vs 规则提取)与去重策略(多久之前的 Plan 仍可召回)是后续优化项,MVP 可简化为"原始 Plan 文本 + 描述字段"。
- 不向长期记忆写入敏感数据(凭证、返回结果中的 PII),除非经过去标识化处理。
