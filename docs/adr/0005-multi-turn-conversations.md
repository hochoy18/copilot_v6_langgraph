# ADR-0005: 多轮会话与上下文保留

## 状态
已接受

## 背景
真实的业务人员工作是迭代的。第一句"查一下 Acme 第三季度的发票"之后,跟着来"把它标为已付"、"谁签的字"、"给法务发一份"。无状态的单次执行强迫用户每轮重述上下文,也无法支持"对上月做同样的事"这类简单追问。

## 决策
系统支持多轮会话。每个会话持久化:

- 完整消息历史(用户轮次与助手响应)
- 活跃的 Plan 与其执行状态
- 每轮组装出的检索上下文窗口

会话是审计归组的基本单位,不是用户轮次。每个用户轮次可触发自己的 Plan 预览,但执行都在更大的会话状态内进行。

## 后果
- 需要会话存储。持久化范围:消息、Plan 快照、执行轨迹、对检索上下文的引用。
- 每轮的检索策略已定型 — 参见 ADR-0007。
- 前端是对话形态,不是命令形态。
- 跨轮的状态卫生很重要:过期状态可能误导 Planner。默认每轮在新的 Plan 预览前重置"活跃 Plan"。
- 多轮会让逐次 HITL 变复杂:第 N 轮的确认会作为上下文带入第 N+1 轮。
