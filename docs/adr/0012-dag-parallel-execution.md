# ADR-0012: DAG 拓扑 — 独立节点并行执行

## 状态
已接受

## 背景
Plan 是带数据依赖边的 Tool 调用 DAG。"查 A 和查 B"这类无依赖的查询,如果串行执行,延迟是两者之和;如果并行,延迟是 max(两者)。但并行引入状态管理复杂度(哪个节点先完成、共享状态如何合并)。

## 决策
Plan 中无依赖边的 Tool 节点并行执行,有依赖边的按拓扑顺序串行。LangGraph 原生支持此模式,通过 StateGraph 的并行分支实现。

- Executor 解析 Plan,构建 LangGraph 子图
- 同一层级无依赖的节点加入并行分支,共享上游 state
- 下游节点等所有上游节点完成后才执行
- 任意并行节点失败 → 整个分支标记失败,等待 HITL 决策(重试 / 跳过 / 中止)

## 后果
- 多 Tool 场景下响应时间显著缩短(从 O(n) 降到 O(关键路径))
- LangGraph 状态管理已处理并行场景,不需要自写调度器
- 失败处理更复杂:并行分支中一个失败不影响其他分支的执行,但 Plan 整体状态需要汇总
- 前端 SSE 推送同一层级的多个 tool.started 事件,UI 自然展示"并行运行中"
