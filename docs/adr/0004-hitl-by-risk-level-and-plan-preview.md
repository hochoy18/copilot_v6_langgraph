# ADR-0004: 按风险等级 HITL + 强制 Plan 预览

## 状态
已接受

## 背景
系统在企业 API 上执行真正的、有副作用的动作。存在两类失效:

1. **操作层面** — 错误的 Tool 被错误参数调用(例如发票重复创建、客户记录被覆盖)。
2. **信任层面** — 业务人员不会采用一个"想打断时打断不了"的系统。

一刀切"每个 Tool 都确认"会让系统不可用;一刀切"全自动执行"又不安全。

## 决策
每次执行有两个 HITL 检查点:

1. **Plan 预览(强制)** — Planner 为用户轮次产出 Plan 后,系统把 Plan 以节点-边图形式展示,等待显式批准后再执行任何 Tool。业务人员可按原样批准、编辑或驳回。
2. **逐次确认(按风险等级)** — `risk_level` 为 `write` 或 `destructive` 的 Tool 在执行前再次确认;`read` 类的 Tool 不打断。

此外,Planner 无法消歧用户轮次意图时(必填参数缺失、目标不明等),系统停下询问。

## 后果
- UX 存在两种独立的打断形态:结构化打断(Plan 图)与内联打断(逐次确认)。前端必须同时支持。
- Plan 预览在 MVP 不可关闭,不存在"自动批准"模式。
- 风险等级是 Tool 的一等属性;在注册时设定,在 OpenAPI 导入时由管理员复核。
- Planner 在无需 Tool 调用、直接由 LLM 回答的场景下(如闲聊、概念解释),可跳过 Plan 预览,直接流式输出最终回答 — 无副作用,不需 HITL。
