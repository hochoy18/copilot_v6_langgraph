# ADR-0002: 三层安全防线

## 状态
已接受

## 背景
产品的"窄而深"卖点是"让企业内部 API 对业务人员可用"。一旦安全失效,客户的内部 API 面就会被泄露给 LLM 提供商、前端,或双方。需要防御三种独立失效模式:

1. **凭证泄露** — API Key 一旦进入 LLM prompt 或前端,瞬间不可逆。
2. **越权** — 业务人员调用了其角色不该接触的 API。
3. **取证失明** — 没人能回答"谁、何时、为何、调了什么"。

## 决策
从 MVP 起,三层必须全部具备:

1. **凭证隔离** — 凭证在后端加密存储,只在调用时刻由不向 LLM 或前端透传密钥的 Worker 注入。
2. **按用户授权** — Tool 注册中心在加载时只暴露该业务人员有权调用的 Tool。LLM 永远看不到用户无权调用的 Tool。
3. **审计追溯** — 每次 Tool 调用产出一条不可改的审计记录(谁、何时、Plan 上下文、参数、结果、状态),写入 MongoDB。

## 后果
- 数据流有硬边界:前端 ↔ 后端、LLM ↔ Tool Worker。任何路径都不能让凭证越过这两道边界。
- 授权必须在业务人员级别建模,需要把 Tool(或更上层的 Tool 组)分配给角色。
- 审计存储只增不改;保留策略详见 ADR-0028(默认 1 年热存 + 3 年冷存)。
- 三层任一缺失即上线阻断项,不是后续优化项。
