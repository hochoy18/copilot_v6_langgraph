# ADR-0028: Audit Log 保留策略 — 1 年热存 + 3 年冷存

## 状态
已接受

## 背景
ADR-0002 说"审计日志默认全保留",但实际 MongoDB 不会无限保留 — 存储成本与备份窗口都有限制。需要明确的热存/冷存策略,既满足合规可调档,又不撑爆存储。

## 决策
Audit Log 保留分两层:

1. **热存(Hot)** — MongoDB,可查可检索。保留 **1 年**。
2. **冷存(Cold)** — 归档存储(对象存储 / 文件系统,具体形态由部署决定),可按需调档。保留 **3 年**(总 4 年)。
3. **迁移机制** — 后台定时任务每天把超过 1 年的日志从 MongoDB 移到冷存,MongoDB 中保留索引条目("此 ID 在冷存,需调档")。
4. **冷存调档** — 管理员后台可触发调档,该日志在 5 分钟内(P95,默认 SLO)回到 MongoDB 可查。
5. **超过 4 年** — 删除(冷存自动过期)。
6. **可配置** — 不同行业 / 客户可能有不同合规年限(金融 5+ 年、医疗 6+ 年),配置项支持覆盖默认值。

## 后果
- 默认 4 年总保留,合规友好且存储可控。
- 冷存形态(S3 / OSS / 本地盘)由部署决定,系统只规定接口不绑死实现。
- 调档有延迟(分钟级),紧急合规场景需要预先规划。
- 冷存数据加密(继承 ADR-0002 的加密标准)。
