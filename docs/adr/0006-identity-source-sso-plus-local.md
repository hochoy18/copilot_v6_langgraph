# ADR-0006: 身份来源 — 企业 SSO + 本地后台账号

## 状态
已接受

## 背景
业务人员的身份是企业级资产,通常已存在于企业的 IdP(Azure AD / Okta / Keycloak / Authing 等)中。本系统若自建账号体系,会与既有 SSO 重复,且对企业 IT 不可接受。后台管理员(包括 Tool 注册、审计查阅)是高权限角色,通常不在 IdP 的常规组织内,需要独立的本地账号。

## 决策
身份分两路,运行时统一:

1. **业务人员** — 通过企业 SSO 联邦登录(OIDC 或 SAML)。身份权威来自 IdP,本系统只读 claim(用户唯一标识、邮箱、组等)。
2. **后台管理员** — 本地账号(用户名 + 密码 + MFA,后续追加)。不在 SSO 路径上,避免 IdP 失效时无法管理。

两条来源在运行时映射为同一个内部 User 记录(`source = sso | local`),后续授权、审计统一以 User 为主键。

## 后果
- 需要 IdP 集成适配层(支持至少 OIDC 与 SAML)。IdP 选型由客户决定,本系统不绑死。
- 本地管理员账号必须有独立的强认证(MFA 强制),因为它不受 IdP 策略约束。
- 用户组/角色信息优先从 IdP claim 同步(SSO 路径),本地管理员手动维护(本地路径)。
- IdP 不可用时,业务人员无法登录,但管理员可以(本地账号独立) — 这是有意保留的运维通道。
