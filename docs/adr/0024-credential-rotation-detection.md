# ADR-0024: 凭证失效感知 — 401/403 触发管理员通知

## 状态
已接受

## 背景
上游 API 的凭证可能因运维轮换、安全事件、或客户方 IdP 配置变更而失效。当前 Tool 调用时会返回 401/403,业务人员会被错误打断,且不知道是凭证问题还是参数问题。

## 决策
Tool 调用收到 401 / 403 时:

1. **不自动重试** — 凭证失效重试无意义(详见 ADR-0017 错误恢复)。
2. **返回结构化错误给 Planner**:
   - 错误类型:`credential_invalid`
   - 错误内容:哪个 Tool 的凭证失效,提示"管理员需轮换"
3. **同步通知管理员** — 后台消息 / 邮件 / IM 提醒,标注:Tool 名、失效时间、最近一次成功调用时间。
4. **Planner 行为** — 看到 `credential_invalid` 时,告诉业务人员"该功能暂时不可用,请联系管理员"。
5. **凭证轮换本身** — 管理员后台操作,更新加密存储的 Credential;系统不自动从 IdP 拉新,保留人工确认步骤。

## 后果
- 业务人员清楚失败原因(凭证失效,不是自己的问题)。
- 管理员被主动告知,可及时轮换。
- 不自动 health-check(避免对客户上游 API 增加调用量);等真实调用触发。
- 长期未使用的 Tool 凭证失效时,业务人员第一次调用才会发现 — 可接受(凭据失效本来就难预测)。
